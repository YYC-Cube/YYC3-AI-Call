```
├──────────────────────────────────────────────────────────┤

├──────────────────────────────────────────────────────────┤
│                   适配层 (Adapters)                        │

│  Sandbox → Registry → API Surface → Event Bus             │

```

### 3.2 核心设计模式

| 模式 | 应用场景 |
|------|----------|
| **观察者模式 (Observer)** | Zustand Store 订阅、WorkflowEventBus 事件通知 |
| **策略模式 (Strategy)** | 多 LLM Provider 切换、多主题渲染策略 |
| **工厂模式 (Factory)** | 插件创建、模型注册 |
| **命令模式 (Command)** | 面板操作、终端命令执行、快捷键绑定 |
| **发布/订阅 (Pub/Sub)** | 跨面板通信、插件间事件传递 |
| **适配器模式 (Adapter)** | IndexedDB/Tauri 存储适配、平台差异屏蔽 |
| **管道模式 (Pipeline)** | AI 管线：上下文收集→意图检测→LLM调用→代码应用 |
| **沙箱模式 (Sandbox)** | 插件隔离执行环境 |

## 四、核心模块深度分析

### 4.1 面板管理系统 (PanelManager)

- **三栏布局**：左面板（AI 对话/模型选择）、中央面板（编辑器/文件管理）、右面板（文件树/预览）
- **支持 21+ 面板类型**：代码编辑、终端、Git、AI 聊天、RAG 知识库、工作流、安全扫描、性能监控等
- **动态操作**：面板拆分、合并、拖拽、固定、浮动、布局持久化（localStorage）

### 4.2 AI 管线系统

```
用户输入 → ContextCollector → SystemPromptBuilder → LLMService → CodeApplicator → 文件更新
              ↓                     ↓                   ↓
         项目上下文           意图检测+提示词构建     SSE 流式输出
```

**支持的 LLM 提供商**：

| 提供商 | 说明 |
|--------|------|
| Ollama | 本地模型运行 |
| OpenAI | GPT 系列 |
| 智谱 GLM | 国产大模型 |
| 阿里 Dashscope | 通义千问 |
| DeepSeek | 深度求索 |
| 自定义 | 通用 OpenAI 兼容接口 |

### 4.3 实时协作系统 (CollabService)

- **核心算法**：Y.js CRDT（无冲突复制数据类型）
- **传输层**：可插拔设计（WebSocket / WebRTC / IndexedDB 离线）
- **功能**：多用户光标感知、实时编辑、冲突自动合并、断线重连
- **离线优先**：支持断网编辑，联网后自动同步

### 4.4 插件系统 (PluginSystem)

```
┌─────────────────────────────────┐
│         Plugin API Surface      │
├────────┬────────┬───────┬───────┤
│Editor  │  UI    │  AI   │Command│
│API     │  API   │  API  │ API   │
├────────┴────────┴───────┴───────┤
│        Event Bus (Pub/Sub)       │
├─────────────────────────────────┤
│        Permission System         │
├─────────────────────────────────┤
│        Sandbox Isolation         │
└─────────────────────────────────┘
```

**已有插件**：AI 助手、代码片段管理、文件浏览器等

### 4.5 安全系统

| 组件 | 功能 |
|------|------|
| **CryptoService** | AES-GCM-256 加密、PBKDF2 密钥派生（≥100,000 轮）、API Key 数据脱敏 |
| **SecurityScanner** | 10 大安全类别扫描（XSS、注入、认证、敏感数据、依赖、CSRF 等） |
| **SecurityPanel** | 可视化安全报告，含 CWE/OWASP 分类和自动修复建议 |

## 五、数据流架构

```
UI 组件  ←→  Zustand Stores  ←→  Services  ←→  Adapters/Bridge
  ↓               ↓
Plugin System    AI Pipeline
  ↓               ↓
Event Bus      LLM Providers
  ↓
CollabService  ←→  Y.js CRDT  ←→  WebSocket/WebRTC
```

**关键数据流路径**：

1. **文件操作流**：用户编辑 → Monaco onChange → FileStore → IndexedDBAdapter → 持久化
2. **AI 交互流**：用户提问 → ContextCollector → PromptBuilder → LLMService (SSE) → 流式响应 → CodeApplicator
3. **协作同步流**：本地编辑 → Y.js Doc → CRDT 合并 → WebSocket 广播 → 远程用户感知
4. **事件通知流**：组件触发 → WorkflowEventBus → 订阅者接收 → 状态更新/面板切换

## 九、架构特点总结

### 优势

| 特点 | 评价 |
|------|------|
| **AI 原生设计** | AI 管线贯穿编辑、生成、诊断全流程，非简单外挂 |
| **模块化程度高** | 17+ 独立 Store、21+ 面板、服务层解耦清晰 |
| **插件化扩展** | 沙箱隔离的插件系统，提供完整的 Editor/UI/AI/Command API |
| **协作能力强** | 基于 CRDT 的实时协作，支持离线优先和冲突自动解决 |
| **安全体系完善** | AES-256 加密、10 大类安全扫描、数据脱敏 |
| **国际化支持** | 三语言覆盖，轻量自研方案 |
| **性能意识** | Worker 管理、懒加载、流式响应、实时监控 |
| **跨平台** | Web + Tauri 桥接，PWA 支持 |

### 架构风格

该 IDE 采用 **事件驱动的模块化分层架构**，核心特征：

1. **前端重度架构** — 大量逻辑在前端实现（AI 管线、协作、文件系统），适合 Web-first 定位
2. **Store 切片化** — 每个功能域独立 Store，避免单一巨大 Store 的复杂性
3. **适配器抽象** — 通过 Bridge/Adapter 层屏蔽平台差异，支持 Web 和桌面端
4. **管道式 AI** — 上下文收集→意图检测→提示词构建→LLM 调用→代码应用，流程清晰
5. **事件总线解耦** — WorkflowEventBus 50+ 事件类型实现跨面板松耦合通信
