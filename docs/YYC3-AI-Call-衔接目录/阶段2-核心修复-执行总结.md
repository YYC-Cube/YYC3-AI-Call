## 💡 经验教训与最佳实践

### 成功经验

1. **分层修复策略有效**
   - P1→P2→P3 的优先级排序确保核心功能最先可用
   - 每完成一层都进行验证，避免回归

2. **类型断言的合理使用**
   - 对于第三方库兼容性问题，`as any` 是实用的临时方案
   - 记录为技术债务，避免遗忘

3. **重复文件的快速识别**
   - 通过错误日志的文件路径快速定位重复文件
   - 果断删除，避免维护负担

### 遇到的挑战

1. **单例模式的接口不一致**
   - `SentimentService`使用单例模式，与其他服务的类实例化模式不同
   - 解决方案：适配调用方而非修改服务本身

2. **第三方库类型爆炸**
   - Recharts的类型定义非常复杂，与React组件属性交叉类型难以匹配
   - 解决方案：`@ts-nocheck` + 技术债务记录

3. **null vs undefined的细微差别**
   - `headers.get()` 返回 `null`，但许多函数期望 `undefined`
   - 解决方案：统一使用 `?? undefined` 转换

### 优化建议

1. **建立类型安全工具库**
   ```typescript
   // lib/type-utils.ts
   export function nullToUndefined<T>(value: T | null): T | undefined {
     return value ?? undefined;
   }

   export function withDefaults<T>(obj: Partial<T>, defaults: Required<T>): T {
     return { ...defaults, ...obj };
   }
   ```

2. **统一AI服务接口规范**
   - 所有AI服务应遵循相同的生命周期：constructor → initialize → use
   - 单例服务应提供显式的 `isReady()` 方法

3. **自动化重复文件检测**
   - 在CI/CD中添加脚本检测 `ui/` 和 `components/ui/` 的重复文件
   - 避免未来再次出现类似问题
