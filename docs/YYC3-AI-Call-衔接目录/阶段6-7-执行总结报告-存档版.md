#### 缓存架构设计

```
请求进入
    ↓
[L1 Memory Cache] ← 本地内存缓存 (~100ms TTL)
    ↓ (miss)
[L2 Redis Cache]  ← 分布式Redis缓存 (~5min TTL)
    ↓ (miss)
[Database]         ← PostgreSQL持久化存储
    ↓
返回结果 + 异步回填缓存
```

#### 核心特性

```typescript
interface MultiLevelCacheOptions {
  l1TTL: number;           // L1缓存TTL (默认100ms)
  l2TTL: number;           // L2缓存TTL (默认5分钟)
  enableL1: boolean;       // 是否启用L1缓存
  enableL2: boolean;       // 是否启用L2缓存
  cacheKeyPrefix: string;  // 键名前缀
}

// 缓存预热机制
async function warmupCache(keys: string[]): Promise<void>

```

#### 7.4.1 结构化日志系统 (logger/index.ts)

**日志级别 (6级)**:

| 级别 | 用途 | 示例场景 |
|------|------|---------|
| TRACE | 最详细的调试信息 | 变量值、函数入口/出口 |
| DEBUG | 开发调试信息 | SQL查询、API调用参数 |
| INFO | 一般业务信息 | 用户登录、任务完成 |
| WARN | 警告信息 | 降级运行、重试操作 |
| ERROR | 错误但可恢复 | 外部API失败、验证失败 |
| FATAL | 致命错误 | 无法启动、数据丢失 |

**核心特性**:

```typescript
// 单例模式
export const logger = Logger.getInstance();

// 结构化日志输出
logger.info('Task completed', {
  requestId: 'req_xxx',
  userId: 'user_123',
  taskCount: 10,
  durationMs: 150,
});

// Request-scoped Logger (请求上下文绑定)
const requestLogger = logger.createRequestLogger(requestId, {
  route: '/api/tasks',
  method: 'GET',
});

requestLogger.debug('Query executed', { sql: 'SELECT * FROM tasks' });
requestLogger.error('DB connection failed', errorObj);
```

**日志格式**:

```
[2026-05-02T10:30:45.123Z] [INFO] Task completed requestId=req_abc123 userId=user_123 taskCount=10 durationMs=150
```
