### 2.2 P0-2 集成测试 19 例失败（✅ 关闭，方案修正为「修复装载链路」）

v1.0.0 建议方案 B（迁移套件至 docs/packages）。实测发现根因是**装载链路缺陷**而非套件归属不当，修复后 61/61 全绿，比迁移更符合「全链路闭环跑通」目标：

| 层级 | 根因 | 修复 |
|---|---|---|
| ① 解析层 | 8 个 `@yyc3/*` 生态包 exports 仅含 `import` 条件（ESM-only），jest-resolve 以 `require/default` 条件解析报 Cannot find module | [jest.config.js](../../jest.config.js) `moduleNameMapper` 增 8 条映射直连 dist 入口 + `^@yyc3/core/(.*)$` 子路径映射（/auth、/ai-family 等） |
| ② 依赖层 | `@yyc3/ai-hub` peerDependencies 声明 `openai >=4.0.0`，pnpm 严格隔离下宿主未装（tsx 真实 Node 环境复现，属真实缺陷） | `pnpm add -D openai` 宿主补装 |
| ③ 产品层 | `config/yyc3-global-config.ts` 的 `standardsCompliance` getter 返回格式化字符串 `"98%"`，测试断言数值失败 | getter 改返数值，`printStatusV2` 展示层加 `%`（展示与数据分离） |
| ④ 运行环境 | openai SDK v6 模块顶层引用全局 `Response`/`TextDecoder` 等 web API，jsdom 环境缺失 | 两个集成测试文件加 `/** @jest-environment node */` docblock（Node 22 自带全套 fetch 全局）；弃用 undici polyfill 方案 |

**证据**：`pnpm exec jest tests/integration` → **61/61 全绿**（整改前 `19 failed, 42 passed`）；同时修正测试自身 3 处缺陷（`i18n.locale` → `getLocale()`、availableLocales 改满配 10 语言、内存断言口径统一 `<150MB`）。

### 2.3 P0-3 API 鉴权覆盖不足（✅ 关闭，含证据修正）

**证据修正**：v1.0.0 统计关键词 `verifyToken` 未匹配 `customers` 路由实际使用的 `verifyAccessToken`，真实基线为 **2/17**（auth、customers），非「3/17 且业务路由 0 接入」。

**整改内容（三档方案落地）**

| 档位 | 路由 | 说明 |
|---|---|---|
| 公开（5） | health、ai/health、auth、auth/oauth、unified-auth | 健康检查与登录换票必须匿名可达 |
| 已保护（1） | customers | 整改前已用 `verifyAccessToken` |
| 强制接入（11） | tenants、tenants/[id]、analytics、ai-family、mcp、multimodal、ws、ai/chat、ai/chat/stream、ai/intent、ai/sentiment | 管理类 7 + 对话类 4 |

1. 新建 [lib/api-auth.ts](../../lib/api-auth.ts)：`requireAuth(request): AuthGate` 同步网关，令牌通道优先级 `Authorization: Bearer` > `access_token` Cookie，401 统一响应体 `{success:false, error, code}`；
2. 11 个业务路由一行接入：`const gate = requireAuth(request); if (!gate.ok) return gate.response;`；
3. 前端 [lib/hooks/useAI.ts](../../lib/hooks/useAI.ts) 3 处 fetch 统一带 `getAuthHeaders()`（[lib/auth-client.ts](../../lib/auth-client.ts)，localStorage 双令牌）；
4. 新增 [tests/unit/lib/api-auth.test.ts](../../tests/unit/lib/api-auth.test.ts) 4 例（有效 Bearer / 缺失 / 无效 / Cookie 通道）全绿；既有 2 个路由逻辑测试注入 `requireAuth` bypass mock（鉴权由专门测试覆盖）。

**证据**：build 路由表 17 条与上表一致；`tests/unit/lib/api-auth.test.ts` 4/4；`pnpm type-check` 0 error。登录 UI 与 HttpOnly Cookie 加固列为演进项（§八）。

## 九、遗留风险与观察项

1. **性能基线（P1-8）**：Lighthouse / bundle 预算未接入，建议按 §八 高性能条目落地 `@lhci/cli`；
2. **全库历史存档断链**：v1.0.0 实测 126 条/16 文件（55 条集中于历史衔接报告），本轮仅收敛验收目录；历史报告按「归档标注」策略分批处理；
3. **令牌存储**：前端 access_token 存 localStorage（XSS 面暴露），演进为 HttpOnly Cookie + Refresh 轮换（§八 高安全条目）；
4. **登录 UI**：后端鉴权已闭环，前端登录页缺失，当前 token 仅会话内存态；
5. **ai-hub peer 依赖**：`openai` 为宿主直装，升级 ai-hub 时需同步核对 peer 区间；
6. **Dependabot 重扫**：esbuild override 修复后待重扫确认告警关闭；
7. **Lint 预算 700**：只减不增，收敛重点 `no-explicit-any`（405）与 `no-unused-vars`（199）。
