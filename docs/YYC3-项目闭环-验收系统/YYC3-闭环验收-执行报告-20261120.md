## 四、P0 阻断项（发布前必须关闭）

### P0-1 组件测试与无障碍自动化缺失

- 证据：`tests/unit` 17 个套件中 `grep -rl "render(" ` = **0**；`package.json` 无 `jest-axe`；无 ErrorBoundary 测试
- 触及条款：COMP-01/02/03/06/07/10（全部 P0）
- 建议：先补 3 个高风险组件（`smart-call-system`、`customer-profile-360`、`ai-chat`）的渲染 + 交互 + axe 断言；预估 **2–3 人日**

### P0-2 集成测试 19 例失败

- 证据：`pnpm test:integration` → `Tests: 19 failed, 42 passed, 61 total`
- 根因：`tests/integration/yyc3-full-integration.test.ts` 期望 8 个 `@yyc3/*` 生态包**已装载**（core/ui/ai-hub/plugins/emotion/mcp-servers/motion/i18n-core），当前仅 `@yyc3/i18n-core` 在依赖树中
- 说明：该套件是「V2.0 全家桶目标态」测试，与当前运行时架构（本地 `lib/ai-family` 实现）不一致
- 决策二选一：
  - A. 按目标态补齐 8 包依赖与初始化（工作量大，改变依赖面）
  - B. 将该套件迁至 `docs/packages/` 工作区并标记为「目标态」，`tests/integration` 只保留与当前架构一致的用例
- 已完成的修复：ESM 载入问题（原为「套件无法运行」），见 §七

### P0-3 API 鉴权覆盖不足

- 证据：`app/api/**/route.ts` 共 **17** 个，含 `getServerSession|verifyToken|requireAuth|authenticate` 的仅 **3** 个
- 触及条款：SEC-003（RBAC 100%）、DTF-002（所有 API 100% 覆盖）
- 建议：明确公开/受保护路由清单，对业务路由统一接入 `lib/auth` 校验；预估 **1–2 人日**

## 六、不适用条款与替代验收方式

| 文档条款 | 不适用的原因 | 本项目替代验收 |
|---|---|---|
| 单元框架：Vitest / MSW | 本项目测试栈为 Jest + RTL；Vitest 仅用于 `docs/packages/*` 生态包 | 以 Jest 等价项验收：Jest 可运行、RTL 已装、Playwright/Husky/CI 生效（均已实测） |
| 第 10 阶段：Lighthouse 分数 | 仓库未配置 Lighthouse CI | 以 `next build` 客观指标替代：构建耗时、First Load JS、路由表；后续接入 LHCI 补齐 |
| 第 11 阶段：AI 自动结论 | AI 结论需人工复核，且无独立模型评测集 | 以静态证据（8 智能体定义、`/api/ai/*` 路由、166 例测试）替代，AI 仅作辅助 |
| 上线运维：灰度 / SLO / 24h 观察 | 项目尚未部署生产，无环境与监控 | 保留门禁项；上线前补「预发布冒烟脚本 + 回滚剧本」，以 `docs` 内既有部署文档为准 |
| 第 2 阶段：FCP / LCP | 无浏览器性能采集链路 | 以 `next build` 产物 + 首屏 JS 体积作为代理指标，标注为「待 LHCI 校准」 |
