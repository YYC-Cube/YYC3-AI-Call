## 七、生产落地判定（GO / NO-GO）

> 判定依据：《全局验收-闭环提示》§五（无未关闭 P0 → 具备条件通过基础）+ 《上线部署-稳定运维》§3.1 门禁表。

### 7.1 判定：**✅ 条件 GO（代码库层面）** / **⏳ NO-GO→GO（生产环境层面，条件明确）**

| 层面 | 判定 | 依据 |
|---|---|---|
| **代码库** | ✅ 条件 GO | 3 P0 全关闭、P1 全关闭（P1-8 于 M2 关闭）、341/341、覆盖率/lint/断链三防倒退门禁全过、合规三件套代码级闭环 |
| **生产环境** | ⏳ 未具备，条件明确 | 尚无生产部署；上线前须完成 §7.2 三条件 + 《上线部署-稳定运维》既有门禁（预发布冒烟 + 回滚剧本 + SLO 实测校准） |

### 7.2 生产 GO 三条件（全部可执行，无模糊项）

1. **供应商连线（约 0.5 天）**：按《POC 执行手册》§一开通三家 → `.env.poc` 注入 → 跑通 ASR×2 + TTS 评测 → 报告落盘 → 五维评分定主备（决策会）；
2. **V1/V2 收口（约 1 周）**：真实 SDK 适配器替换 POC 验证路径（接口已定型）、`/api/telemetry/latency` + Redis 缓冲（V2）、延迟实测回写 SLO 校准；
3. **部署链路（约 2-3 天）**：预发布环境 + 冒烟脚本 + 回滚剧本（文档已有骨架）+ 首次生产部署演练 + 24h 观察（SLO：可用性 ≥99.9%、TTFT P95 ≤200ms、错误率 ≤0.5%）。

### 7.3 明确不建议上线的行为（红线）

- 未跑供应商真实评测即上语音功能（合规五道闸依赖号码台账数据，空库即全阻断——设计如此，需先录入真实号码与授权凭证）；
- 凭证以任何形式进入仓库或 CI 明文；
- 覆盖率阈值下调或 lint 预算上调以「让测试过」。
